# نظرة معمّقة: المحادثة والتعاون في الوقت الفعلي

## ما هو نظام المحادثة المبني أصلًا على الذكاء الاصطناعي؟

تنقل أنظمة المحادثة التقليدية النصوص بين البشر. أما نظام المحادثة المبني أصلًا على الذكاء الاصطناعي (AI-native) فيعامل **وكلاء الذكاء الاصطناعي (AI Agents) بوصفهم مشاركين أصيلين**: فهم يقرؤون الرسائل، ويفهمون السياق، ويبثّون ردودهم تدريجيًا، ويستدعون الأدوات، ويعرضون عناصر تفاعلية، وكل ذلك داخل سلسلة المحادثة نفسها التي يستخدمها البشر.

ليس هذا «دردشة ذكاء اصطناعي» منفصلة تُلصق بمنتجك، بل طبقة تواصل موحّدة يتعاون فيها البشر والذكاء الاصطناعي بشكل طبيعي.

## أنواع المحادثات

يدعم نظام المحادثة أربعة نماذج من المحادثات تغطي جميع أنماط التواصل:

| النوع | الوصف | مثال |
|---|---|---|
| **خاصة (مستخدم)** | مراسلة فردية بين مستخدمَين | رسالة مباشرة إلى زميل |
| **خاصة (وكيل)** | محادثة فردية مع وكيل ذكاء اصطناعي | طرح سؤال على وكيل «Product Analyst» |
| **مجموعة** | محادثات متعددة المشاركين | قناة فريق مشروع تضم مستخدمين ووكلاء معًا |
| **سياقية** | محادثة مدمجة داخل ميزة أو صفحة بعينها | سلسلة نقاش حول مواصفات ميزة |

تعتمد جميع أنواع المحادثات على البنية التحتية نفسها: فالرسائل والمرفقات والتسليم في الوقت الفعلي ومشاركة الذكاء الاصطناعي تعمل كلها بالطريقة ذاتها أيًّا كان نوع المحادثة.

## أنواع الرسائل ومحتواها

### الرسائل النصية

رسائل نصية قياسية تتضمن:
- عرضًا كاملًا لصيغة Markdown (العناوين، والقوائم، وكتل الشيفرة، والروابط، والخط العريض، والمائل)
- إشارات @ (Mentions) مع روابط قابلة للنقر إلى المستخدمين والوكلاء
- نسخ أي رسالة إلى الحافظة

### الرسائل الصوتية

مسار متكامل للمراسلة الصوتية:

```
Record → Preview → Send → Auto-Transcribe
```

1. **التسجيل**: التقاط الصوت من المتصفح مع عرض مرئي لمستوى الصوت في الوقت الفعلي ومؤقّت
2. **المعاينة**: الاستماع إلى التسجيل قبل إرساله، مع إمكانية حذفه وإعادة التسجيل
3. **التسليم**: رفع الصوت إلى التخزين السحابي، وتسليم الرسالة مع أدوات التحكم في التشغيل
4. **التفريغ النصي**: تحويل الكلام إلى نص في الخلفية، فيصبح الصوت تلقائيًا نصًا قابلًا للبحث

تكتسب الرسائل الصوتية قيمة خاصة في الحالات التالية:
- المستخدمون الذين يعتمدون على الهاتف أولًا ويحتاجون إلى التواصل دون استخدام اليدين
- العاملون الميدانيون الذين يرفعون تقاريرهم من مواقع العمل
- إمكانية الوصول، للمستخدمين الذين تصعب عليهم الكتابة
- التقاط الفروق الدقيقة التي يُفقدها النص

### المرفقات

السحب والإفلات أو النقر للرفع، مع:
- **دعم الصور**: JPEG وPNG وGIF وWebP مع عرضها ضمن الرسالة وطبقة تظهر عند تمرير المؤشر
- **دعم المستندات**: PDF وTXT وMarkdown مع بطاقات تعرض اسم الملف ونوعه وحجمه
- **عدة ملفات** في الرسالة الواحدة
- **شريط معاينة** قبل الإرسال لمراجعة الملفات وإزالة ما لا تريده قبل إرساله
- **زر تنزيل** على الملفات المستلَمة

يتبع الرفع مسارًا آمنًا من ثلاث خطوات:
1. طلب رابط رفع موقَّع مسبقًا (Presigned URL) من الخادم
2. الرفع مباشرة إلى التخزين السحابي (S3)
3. تأكيد الرفع وإرفاق البيانات الوصفية بالرسالة

يعني هذا التصميم أن الملفات لا تمر أبدًا عبر خادم التطبيق، مما يخفّف الحمل ويقلّل زمن الاستجابة.

### رسائل النظام

إشعارات تلقائية لأحداث المحادثة:
- إنشاء مجموعة («أنشأت Alice هذه المجموعة»)
- تغييرات المشاركين («أُضيف Bob إلى المحادثة»)
- أحداث نظام مخصّصة صادرة عن التكاملات

## العناصر التفاعلية

هنا يتجاوز نظام المحادثة المراسلة التقليدية؛ إذ يمكن أن تحتوي الرسائل على **مكوّنات قابلة للتنفيذ** يتفاعل معها المستخدمون مباشرة:

| نوع العنصر | الوصف | مثال |
|---|---|---|
| **اقتراح تعديل (Diff)** | يقترح الذكاء الاصطناعي تغييرًا على شيفرة أو مستند، ويستطيع المستخدم قبوله أو رفضه في مكانه. | يقترح الوكيل إصلاحًا: «غيّر السطر 42 من X إلى Y»، فينقر المستخدم على «قبول» |
| **إدراج متدفّق** | يبثّ الذكاء الاصطناعي محتوى داخل مستند في الوقت الفعلي، مع أدوات للإتمام أو الرفض | يكتب الوكيل قسمًا من مواصفات ميزة بينما يتابعه المستخدم |
| **نموذج** | جمع بيانات منظّمة ضمن سياق المحادثة | يطلب الوكيل معاملات الإعداد عبر نموذج |
| **تأكيد** | نقطة قرار بنعم أو لا مع سياقها | يسأل الوكيل: «هل أنشر هذا على بيئة staging؟» |
| **مجموعة أسئلة** | استبيان متعدد الأسئلة بخانات اختيار وأزرار اختيار أحادي | استبيان تأهيل مع أسئلة متابعة يقودها الذكاء الاصطناعي |

يتتبّع كل عنصر تفاعلي حالته الخاصة (`pending` → `accepted`/`rejected`/`completed`/`failed`)، وتُطلق تغييرات الحالة أحداثًا يمكن للأنظمة الأخرى التفاعل معها.

**لماذا يهم هذا:** لا يحتاج المستخدمون إلى مغادرة المحادثة لاتخاذ إجراء. الذكاء الاصطناعي يقترح، والمستخدم يقرّر، والنظام ينفّذ، وكل ذلك في مكان واحد.

## الإشارات والوسوم

يربط نظام إشارات @ بين البشر والذكاء الاصطناعي:

1. **اكتب `@`** في حقل الإدخال لفتح قائمة الاقتراحات
2. **صفِّ النتائج** بالكتابة، فتضيق الاقتراحات في الوقت الفعلي
3. **اختر** مستخدمًا أو وكيل ذكاء اصطناعي أو جهاز CLI
4. **تُدمج الإشارة** في الرسالة على شكل وسم منظّم

عندما تتضمن رسالة إشارة إلى وكيل ذكاء اصطناعي، يقوم النظام تلقائيًا بما يلي:
- توجيه الرسالة إلى مسار المعالجة الخاص بالوكيل
- إرفاق سجل المحادثة الحديث بوصفه سياقًا
- بدء بثّ رد الوكيل تدريجيًا داخل المحادثة

### الوكلاء الملازمون

في المحادثات المستمرة مع وكيل بعينه، تضيف ميزة «الوكيل الملازم» (Sticky Agent) الوكيلَ تلقائيًا إلى كل رسالة دون الحاجة إلى إشارة @ يدوية. يُحفظ هذا الإعداد لكل محادثة على حدة ويبقى قائمًا بين الجلسات.

## التسليم في الوقت الفعلي

تُسلَّم الرسائل في الوقت الفعلي باستخدام **الأحداث المرسلة من الخادم (Server-Sent Events - SSE)**:

```
Client                          Server
  │                                │
  │── GET /api/chat/events ───────>│
  │                                │
  │<── event: message ────────────│  (new message)
  │<── event: message ────────────│  (streaming chunk)
  │<── event: heartbeat ──────────│  (keep-alive)
  │<── event: message ────────────│  (another message)
  │                                │
  │── (connection timeout) ───────>│
  │── GET /api/chat/events ───────>│  (auto-reconnect)
  │                                │
```

**استطلاع ذكي يتكيّف مع السياق:**
- **أثناء بثّ ردود الذكاء الاصطناعي**: استطلاع كل ثانية واحدة لتدفّق سلس للرموز (Tokens)
- **في التشغيل العادي**: استطلاع كل 3 ثوانٍ حرصًا على الكفاءة
- **على الأجهزة المحمولة**: مدة اتصال قصوى أقصر (دقيقتان) للحفاظ على البطارية
- **مهلة الاتصال**: 10 دقائق كحد أقصى مع إعادة اتصال تلقائية

**اكتشاف التغييرات** محسَّن:
- اكتشاف تحديثات المحتوى في الردود المتدفّقة
- اكتشاف تغييرات السياق عند تحديث البيانات الوصفية
- اكتشاف الرسائل الجديدة في التسليم القياسي
- إرسال البيانات المتغيّرة فقط

## بثّ ردود الذكاء الاصطناعي تدريجيًا

عندما يرد وكيل ذكاء اصطناعي، يتدفّق الجواب إلى المحادثة رمزًا تلو الآخر:

1. تظهر رسالة مؤقتة فورًا مع الصورة الرمزية للوكيل
2. يتدفّق النص تدريجيًا بالتزامن مع توليد النموذج له
3. تُعرض استدعاءات الأدوات في الوقت الفعلي (ليرى المستخدمون ما يفعله الوكيل)
4. تكتمل الرسالة عند انتهاء التوليد

يتولّى **مخزن مؤقت للبث (Stream Buffer)** إدارة هذا التدفّق:
- تُجمع الأجزاء وتُفرَّغ كل 200 مللي ثانية
- تمنع عمليات الكتابة الذرّية في قاعدة البيانات حالات التسابق (Race Conditions)
- تحافظ ضمانات الكتابة المتسلسلة على تماسك الرسالة

ينتج عن ذلك تجربة طبيعية سريعة الاستجابة، إذ يرى المستخدمون الذكاء الاصطناعي «يفكّر» بدلًا من انتظار رد مكتمل.

## الإشعارات وتتبّع الرسائل غير المقروءة

### عدّادات غير المقروء

تسجّل كل محادثة **طابعًا زمنيًا لآخر قراءة** لكل مستخدم. وتُحسب عدّادات الرسائل غير المقروءة بمقارنة هذا الطابع الزمني بالرسائل الجديدة، مع استثناء رسائل النظام.

### الإشعارات الصوتية

تنبيهات صوتية قابلة للضبط عند وصول رسائل جديدة، مع إدارة تفضيلات المستخدم.

### أحداث الإشعارات في الوقت الفعلي

تسلّم قناة SSE مخصّصة أحداث الإشعارات (معاينات الرسائل الجديدة، ومعلومات المرسل)، فتتمكّن الواجهة من تحديث الشارات والمؤشرات دون استطلاع قوائم المحادثات.

## إدارة المحادثات الجماعية

إدارة كاملة لدورة حياة المحادثات متعددة المشاركين:

| العملية | الوصف |
|---|---|
| **إنشاء** | اختيار المشاركين (مستخدمون + وكلاء)، وتسمية المجموعة، مع إضافة المنشئ تلقائيًا |
| **دعوة** | إضافة مشاركين جدد مع إشعار عبر رسالة نظام |
| **مغادرة** | الانسحاب من المجموعة مع نافذة تأكيد |
| **تعديل** | تحديث اسم المجموعة وقائمة المشاركين |

تدعم المجموعات الميزات نفسها المتاحة في المحادثات الخاصة: المرفقات، والرسائل الصوتية، ووكلاء الذكاء الاصطناعي، والعناصر التفاعلية، والإشارات.

## التقسيم إلى صفحات والسجل

يعتمد سجل المحادثة على **التقسيم إلى صفحات بالمؤشر (Cursor-based Pagination)** لتحميل فعّال:

- **التحميل الأولي**: أحدث 10 رسائل
- **تحميل المزيد**: 15 رسالة في كل صفحة، يُطلَق عند التمرير قرب الأعلى
- **ثنائي الاتجاه**: تحميل الرسائل الأقدم أو الأحدث بالنسبة إلى المؤشر
- **إدارة التمرير**: تمرير تلقائي إلى الأسفل عند وصول رسائل جديدة، وشارة «رسائل جديدة» عند التمرير إلى الأعلى

## تحليلات الاستخدام

يوفّر نظام المحادثة تحليلات مدمجة:

| المقياس | الوصف |
|---|---|
| **إجمالي الرسائل** | الحجم الكلي للرسائل |
| **المحادثات الفريدة** | عدد السلاسل النشطة |
| **المستخدمون النشطون** | المشاركون البشريون المتمايزون |
| **الرسائل حسب العضو** | عدد الرسائل لكل مستخدم |
| **الرسائل حسب الوكيل** | عدد الرسائل لكل وكيل |
| **التوزيع اليومي** | نشاط الأعضاء مقابل نشاط الوكلاء عبر الزمن |
| **التوزيع حسب المشروع** | حجم الرسائل في كل مشروع |

تتيح هذه المقاييس:
- فهم أنماط التواصل داخل الفريق
- قياس مدى اعتماد وكلاء الذكاء الاصطناعي وفعاليتهم
- تحديد المناطق عالية النشاط التي قد تحتاج إلى موارد إضافية
- إعداد التقارير للإدارة وأصحاب المصلحة

## الأمان وتعدد المستأجرين

| الميزة | الوصف |

## سياق الرسالة وقابلية التوسّع

تحمل كل رسالة **كائن سياق** يمكن أن يتضمن:

- مراجع المستخدمين الموسومين
- مؤشرات حالة البث
- البيانات الوصفية لوكلاء CLI (اسم الجهاز، والنموذج، وزمن الاستجابة)
- مراجع الرد على رسالة (أساس سلاسل النقاش)
- مصفوفات العناصر التفاعلية
- البيانات الوصفية للمرفقات
- البيانات الوصفية للصوت (نوع MIME، والمدة، وحالة التفريغ النصي)
- معلومات المنطقة الزمنية
- حالة الفهرسة للبحث

يعني نموذج السياق القابل للتوسّع هذا إمكانية إضافة ميزات جديدة إلى الرسائل دون ترحيل مخطط قاعدة البيانات (Schema Migrations)، إذ تُخزَّن حقول السياق بصيغة JSON وتفسّرها طبقة الواجهة.

## الخلاصة

نظام المحادثة ليس مجرد مراسلة، بل هو **بيئة تشغيل للتعاون** تقوم بما يلي:

1. **توحيد البشر والذكاء الاصطناعي** في سلاسل المحادثة نفسها
2. **دعم الوسائط الغنية**: النصوص والصوت والملفات والمكوّنات التفاعلية
3. **التسليم في الوقت الفعلي** مع بثّ تكيّفي وإشعارات
4. **تمكين الفعل** عبر عناصر تفاعلية تتيح للمستخدمين اتخاذ القرار والتنفيذ دون مغادرة المحادثة
5. **تتبّع كل شيء** عبر التحليلات وسجلات التدقيق وإدارة الرسائل غير المقروءة
6. **التوسّع عبر المشاريع** مع عزل متعدد المستأجرين وصلاحيات وصول قابلة للضبط

هذه هي طبقة التواصل التي تحتاجها المنتجات الحديثة المعزَّزة بالذكاء الاصطناعي، حيث تصبح كل محادثة فرصة للأتمتة الذكية.
